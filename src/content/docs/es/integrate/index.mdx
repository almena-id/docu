Almena está abierto a tus sistemas en cada paso que una persona da en los
portales. Todo lo que hace el registry está en su API, y la API decide: los
portales no comprueban nada que ella no vuelva a comprobar.

## Las puertas

| Puerta | Dónde | Para |
| --- | --- | --- |
| **API REST** | `https://api.almena.id/api/v1` | Todo: cuentas, emisores, verificadores, formularios, solicitudes, verificaciones |
| **CLI `almena`** | macOS, Linux, Windows | Lo mismo, desde un terminal o un pipeline |
| **Colas** | AMQP, una por emisor y verificador | Lo que les llega, en cuanto llega |
| **MCP** | `/mcp` de la API | Asistentes de IA que trabajan con el registry |
| **Agente** | `https://agent.almena.id`, A2A 1.0 | Otros agentes que preguntan por Almena |

## Los estándares que habla

Almena usa estándares abiertos, así que cualquier wallet o verificador que los
hable funciona con él:

- **Credenciales**: SD-JWT VC (`dc+sd-jwt`), con divulgación selectiva: el
  titular enseña solo los datos que se piden.
- **Pedir credenciales**: OpenID for Verifiable Presentations, con consultas
  DCQL.
- **Entrar con un wallet**: Self-Issued OpenID Provider v2.
- **Identidades**: `did:webvh` para organizaciones y servicios, `did:peer` y
  `did:key` para wallets.
- **Retirar credenciales**: IETF Token Status List.
- **Mensajes entre wallets**: DIDComm Messaging v2.0, a través de un mediador.
