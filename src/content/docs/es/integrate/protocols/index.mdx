## Entre un wallet y el registry

Los portales del registry muestran un código QR con el enlace del wallet,
`https://almena.id/w/…` —el mismo que `almena://…`, pero un enlace que solo el
wallet de Almena puede abrir, porque `almena.id` lo nombra (universal links de
iOS, `/.well-known/apple-app-site-association`; App Links de Android,
`/.well-known/assetlinks.json`)—; el wallet lee la petición del dominio de
identidad (`almena.id`) y responde allí.

| Para qué | Estándar | Qué viaja |
| --- | --- | --- |
| Entrar, vincular un wallet, emparejarse con un emisor | [Self-Issued OpenID Provider v2](https://openid.net/specs/openid-connect-self-issued-v2-1_0.html), `direct_post` | Un `id_token` (JWS, `EdDSA`) para el `nonce` de la petición, con una clave derivada por registry o por emisor |
| Presentar credenciales | [OpenID for Verifiable Presentations](https://openid.net/specs/openid-4-verifiable-presentations-1_0.html), consultas DCQL | Un `vp_token`: SD-JWT VC con solo los datos pedidos, cada una con su `kb+jwt` |
| Firmar una entrada del registro de una identidad | [`did:webvh`](https://identity.foundation/didwebvh/) + Data Integrity `eddsa-jcs-2022` | Una prueba sobre la entrada canónica (JCS) |
| Firmar una credencial o una lista de estado | JWS (`EdDSA`) | La firma del emisor sobre lo que mostró la hoja |

## Las credenciales y su estado

| Tema | Estándar |
| --- | --- |
| Formato | [SD-JWT-based Verifiable Credentials](https://datatracker.ietf.org/doc/draft-ietf-oauth-sd-jwt-vc/) (`dc+sd-jwt`), con su Type Metadata en `https://almena.id/.well-known/vct/…` |
| Esquemas de los datos | JSON Schema 2020-12, en `https://almena.id/schemas/…` |
| Revocación y suspensión | [IETF Token Status List](https://datatracker.ietf.org/doc/draft-ietf-oauth-status-list/) |
| Identidades de las organizaciones | [`did:webvh` 1.0](https://identity.foundation/didwebvh/), resueltas desde `almena.id` |
| Identidades de los wallets | `did:peer:2` (relaciones, la tarjeta de invitación), `did:key` (emparejar, entrar) |

## Entre wallets

Los wallets solo hablan a través de mediadores, con
[DIDComm Messaging v2.0](https://identity.foundation/didcomm-messaging/spec/v2.0/):
sobres cifrados de punta a punta que el mediador guarda y reenvía sin poder
leerlos.

| Protocolo | Uso |
| --- | --- |
| Coordinate Mediation 3.0, Routing 2.0, Message Pickup 3.0 (modo en vivo) | El buzón de un wallet en su mediador |
| Trust Ping 2.0, Out-of-Band 2.0 | Abrir una relación a partir de una invitación |
| Basic Message 2.0, User Profile 1.0 | Texto, y el nombre de cada parte |
| Almena calls 1.0, Almena TURN 1.0 | Llamadas de voz y vídeo, por el servidor TURN del mediador |
