Almena is open to your systems at every step a person goes through in the
portals. Everything the registry does is in its API, and the API decides:
the portals check nothing it does not check again.

## The doors

| Door | Where | For |
| --- | --- | --- |
| **REST API** | `https://api.almena.id/api/v1` | Everything: accounts, issuers, verifiers, forms, applications, verifications |
| **`almena` CLI** | macOS, Linux, Windows | The same, from a terminal or a pipeline |
| **Queues** | AMQP, one per issuer and verifier | What arrives for them, as it arrives |
| **MCP** | the API's `/mcp` | AI assistants working with the registry |
| **Agent** | `https://agent.almena.id`, A2A 1.0 | Other agents asking about Almena |

## The standards it speaks

Almena uses open standards, so any wallet or verifier that speaks them works
with it:

- **Credentials**: SD-JWT VC (`dc+sd-jwt`), with selective disclosure — a
  holder shows only the claims asked for.
- **Asking for credentials**: OpenID for Verifiable Presentations, with DCQL
  queries.
- **Signing in with a wallet**: Self-Issued OpenID Provider v2.
- **Identities**: `did:webvh` for organisations and services, `did:peer` and
  `did:key` for wallets.
- **Withdrawing credentials**: IETF Token Status List.
- **Messages between wallets**: DIDComm Messaging v2.0, through a mediator.
